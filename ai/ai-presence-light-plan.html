01方案架构

夜灯已接入 Home Assistant，所以本方案不碰灯具本身：LD2410B 只负责「有没有人」这一个信号，经 ESPHome 转成 HA 实体，联动逻辑全部放在 HA 自动化里——以后想改延迟时间、加夜间条件、联动别的灯，都不用动硬件。

为什么用「存在」而不是「移动」做主信号

🚶 移动目标（moving）

检测走动、挥手等大幅动作，响应快，但人静坐约半分钟后就会丢失 → 单用它做夜灯，看电视时灯会反复熄灭。

🧘 静止目标（still）

检测呼吸级微动，人坐着躺着都能持续保持 → 夜灯联动的正确主信号。LD2410B 的 has_target（移动 OR 静止）就是两者取或，直接用它最省心。

✅ 和 PIR 的对比：PIR（如小米人体传感器）只能测「红外变化」，人静止 1~2 分钟就判定无人，夜灯会在你看电视时突然熄灭。毫米波雷达测的是多普勒微动，睡着都能保持检出——这正是「待在客厅就开灯」需求的关键。

03接线表

LD2410B 只有几个焊盘，接 4 根线就能跑。以 ESP32 为例（其他板换对应引脚即可）。

LD2410B 焊盘接 ESP32说明
VCC5V（VBUS/5V 脚）⚠️ 建议 5V 供电，接 3.3V 会不稳定、探测距离缩水（板载 LDO 给雷达芯片供电）
GNDGND共地
TXGPIO 16（ESP 的 RX）交叉接：雷达 TX → ESP RX；3.3V 逻辑可直连，无需电平转换
RXGPIO 17（ESP 的 TX）交叉接：雷达 RX ← ESP TX；供调参/配置用，建议接上
OUT（OT）可不接GPIO 高/低电平直出「有无目标」，本方案走 UART 拿更丰富的数据，用不到它
⚠️ 最容易踩的坑：TX/RX 一定要交叉（雷达 TX 接 ESP 的 RX，雷达 RX 接 ESP 的 TX）。接反了 ESPHome 日志会一直刷「找不到雷达」。
📌 波特率：LD2410B 出厂 UART 固定 256000（不是常见的 9600/115200），ESPHome 里必须写对，下一节 YAML 已给出。

04ESPHome 固件配置

推荐用 ESPHome Web 工具（web.esphome.io）浏览器直刷，或在 HA 里装 ESPHome 加载项（推荐，改配置点一下就 OTA 升级）。

完整 YAML（living-room-presence.yaml）

esphome:
  name: living-room-presence
  friendly_name: 客厅存在传感器

esp32:            # ESP8266 板改成 esp8266: + board: esp01_1m
  board: esp32dev

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
  ap:              # 配网失败时开热点兜底
    ssid: "Presence Fallback"
    password: "12345678"

captive_portal:
logger:
api:
ota:
  - platform: esphome

uart:
  tx_pin: GPIO17
  rx_pin: GPIO16
  baud_rate: 256000   # LD2410B 固定波特率
  parity: NONE
  stop_bits: 1

ld2410:
  id: ld2410_radar

binary_sensor:
  - platform: ld2410
    has_target:            # 移动 OR 静止，主信号就用它
      name: "客厅存在"
    has_moving_target:
      name: "客厅移动"
    has_still_target:
      name: "客厅静止"

sensor:
  - platform: ld2410
    moving_distance:
      name: "移动距离"
    still_distance:
      name: "静止距离"
    moving_energy:
      name: "移动能量"
    still_energy:
      name: "静止能量"
    detection_distance:
      name: "探测距离"

  # 可选：板载温度/信号，便于排查
  - platform: wifi_signal
    name: "WiFi 信号"
    update_interval: 60s
✅ 刷完后 HA 里会自动发现这台 ESPHome 设备（设置 → 设备与服务 → 发现）。点「配置」即可，binary_sensor.客厅存在 等实体全部自动生成，无需手写 MQTT。
💡 只要主信号的话，sensor: 那几行距离/能量可以删掉，但留着方便在 HA 里画曲线调灵敏度，建议先保留。

05Home Assistant 自动化

核心逻辑：检测到人 → 立即开灯；连续 5 分钟无人 → 关灯。一个自动化搞定，YAML 模式直接粘贴（设置 → 自动化 → 新建 → 右上角切换到 YAML 编辑）。

automation.yaml

alias: 客厅夜灯 · 人来灯亮人走灯灭
description: LD2410B 存在感应联动夜灯
mode: restart
trigger:
  - platform: state
    entity_id: binary_sensor.ke_ting_cun_zai   # 客厅存在
    to: "on"
    id: enter
  - platform: state
    entity_id: binary_sensor.ke_ting_cun_zai
    to: "off"
    for: "00:05:00"        # 无人持续 5 分钟才关灯
    id: leave
condition: []
action:
  - choose:
      - conditions: "{{ trigger.id == 'enter' }}"
        sequence:
          - service: light.turn_on
            target:
              entity_id: light.living_room_night_light  # 换成你的夜灯实体
      - conditions: "{{ trigger.id == 'leave' }}"
        sequence:
          - service: light.turn_off
            target:
              entity_id: light.living_room_night_light
⚠️ entity_id 要换成你 HA 里实际的实体名：存在传感器刷完后可能是拼音（如上），夜灯实体去「开发者工具 → 状态」里搜 light. 确认。

可选增强：只在夜间生效

白天客厅有自然光，夜灯没必要亮。把 condition: [] 换成：

condition:
  - condition: state
    entity_id: sun.sun
    state: "below_horizon"   # 仅日落后到日出前生效

也可以用时间段（如 18:00~次日 7:00），或加一个 input_boolean 总开关方便临时停用。

调延迟不用改自动化

「离开多久关灯」的 for: 00:05:00 就是缓冲期。毫米波本身有约 2~3 秒的无人延迟判定（下节可调），加上这个 5 分钟，基本不会出现「人还在灯先灭」的尴尬。嫌保守可缩到 2~3 分钟。

06灵敏度调优

LD2410B 出厂默认参数就能用，但客厅场景建议花 10 分钟调一下。两条路：手机 App 走蓝牙（B 版专属，最方便），或 HA 里用 ESPHome 的 number 实体调。

📱 方式一：HLKRadarTool App（推荐）

  1. 手机装 HLKRadarTool（Android/iOS 均有，官方免费）
  2. 雷达上电后 App 扫描蓝牙直连（不需要 ESP 参与）
  3. 可视化界面里调：移动/静止灵敏度（每个距离门 0~100）、无人延迟（0~65535 秒，建议 5~15）、最大探测距离门
  4. 调完点写入，参数存进雷达掉电不丢

注：调参时雷达 RX 必须接着 ESP（或 USB 转 TTL），App 通过蓝牙发配置指令。

🏠 方式二：ESPHome number 实体

在上面 YAML 的 ld2410: 下面加几行，HA 里就会出现滑条，不用碰手机：

number:
  - platform: ld2410
    timeout:
      name: "无人延迟"
    max_move_distance_gate:
      name: "最大移动距离门"
    max_still_distance_gate:
      name: "最大静止距离门"
    still_sensitivity:
      name: "静止灵敏度"
    moving_sensitivity:
      name: "移动灵敏度"

客厅场景调参建议

参数建议值原因
距离门（gate）开到 4~5 门（约 3~3.75m）每门 0.75m；把覆盖范围限制在客厅内，避免隔着墙/走廊误触发
移动灵敏度60~70（默认 50 起调）走动检出更快
静止灵敏度50~60太高会把风扇/窗帘当人；太低人静坐会丢
无人延迟5~10 秒HA 自动化里已有 5 分钟缓冲，这里不用太长
🎯 调试技巧：在 HA 里把「静止能量」「移动能量」两个传感器加到仪表盘，人坐在沙发上观察能量值——数值稳定高于阈值 = 灵敏度合适；时掉时回 = 调高静止灵敏度一档。

07安装位置与朝向

毫米波雷达是「锥形波束」探测，装对位置比调参数更重要。24GHz 能穿透木板/石膏板/薄窗帘，但会被金属和厚墙挡住。

✅ 推荐装法

  • 客厅对角天花板角落：波束斜向下覆盖全屋，探测最均匀（首选）
  • 墙面 2~2.4m 高：朝人常待的区域（沙发/餐桌）斜向下 30~45°
  • 正对主要活动区，中间无大家具/绿植遮挡
  • 用双面胶或 3D 打印支架固定，避免晃动

❌ 避开这些

  • 正对电风扇/空调出风口/摇摆的窗帘：周期性运动会误触发（最常见误报源）
  • 正对门口/走廊：路过的人会被算进客厅 → 用「距离门」裁掉远处，或调朝向
  • 金属板/镜子正后方或正前方
  • 紧贴大型家电（冰箱/电视背面），电磁干扰 + 遮挡
💡 先裸板验证再固定：接线后用杜邦线临时引出来，拿在手里在客厅各处走一圈，看 HA 里「存在」实体是否跟着亮，确定最佳点位再上胶固定。

09风险与注意事项

⚠️ 硬件坑

  • 供电必须稳：雷达对电源纹波敏感，别和功放类大功率器件共用一个 USB 口；本项目整机 <1W，普通充电头没问题。
  • TX/RX 交叉：接反不烧板子，但完全无数据；日志刷「uart error」先查这里。
  • 波特率 256000：非常规值，手抄 YAML 时最容易写错成 115200。
  • 杜邦线接触不良：雷达模块焊盘小，长期部署建议焊接或热熔胶固定杜邦头。

🏠 使用场景坑

  • 误触发源：风扇、空调摆风、飘动窗帘、宠物——毫米波对任何周期性微动都会响应。靠朝向 + 距离门 + 灵敏度三板斧压制。
  • 隔墙探测：24GHz 能穿透石膏板/木门，装在客厅却可能探测到隔壁房间的人 → 距离门裁短或换朝向。
  • 金属遮挡：雷达不能装在金属盒/金属贴膜后面，波束被完全屏蔽。
  • HA 依赖：自动化在 HA 里跑，HA 重启/挂掉期间夜灯不联动（灯本身不受影响）。追求高可用可把逻辑下放：雷达 OUT 脚 + 智能开关本地联动，二期再考虑。
  • 隐私：雷达只输出「有无目标 + 距离 + 能量」，不采集任何图像/声音，卧室客厅均可放心用。
