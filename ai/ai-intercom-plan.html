✅ 为什么选 ESP32-S3 而不是 ESP32？ ① 支持向量指令，可跑 ESP-SR 离线唤醒词；② 原生 USB，烧录/调试免驱动板；③ PSRAM 是 Opus 音频流缓冲的硬需求（xiaozhi 明确要求 ≥8MB PSRAM 版本）；④ 生态：xiaozhi-esp32 对 S3 支持最完善。
💡 替代方案：如果想省接线功夫，可以直接买 立创·实战派 ESP32-S3（¥60 左右，自带麦克风+喇叭+屏+旋钮按键）或 M5Stack CoreS3，xiaozhi 均有现成板级支持。但自搭面包板更贴合你"跳线/焊接"的一期目标，且成本更低、扩展自由。

🚦 三色指示灯状态定义（WS2812）

灯色状态触发时机
🟢 绿色（常亮）收音中按下 PTT 按钮、I2S 开始采集即亮；松开燄灭
🟡 黄色（常亮）输出中收到服务端 TTS 音频、喇叭开始播放即亮；播完燄灭

实现：xiaozhi 固件板级配置自带状态灯（listening/speaking 状态可映射颜色），绿=Listening、黄=Speaking 开箱即用；红灯故障需在固件里小改几行（断网/报错时调 SetStatusLedColor 切红色）。若用 3 颗单色 LED 替代，则各占一个 GPIO，固件逻辑相同。

05软件方案

两条路线：方案 A 基于开源项目 xiaozhi-esp32 快速落地（强烈推荐一期使用）；方案 B 全自研固件，二期需要深度定制时再切换。

方案 A（推荐）：xiaozhi-esp32 开源生态

GitHub 78/xiaozhi-esp32（MIT 协议），就是为你这个场景而生的：按键说话、Opus 流式传输、WebSocket / MQTT+UDP 双协议、OLED 表情、MCP 设备控制、Web 控制台配模型。

  • 固件：ESP-IDF v6.0.1+ 编译，或直接刷免编译固件（138 种板型）
  • 音频：ESP-SR 离线唤醒 + AEC + Opus 编解码，全部内置
  • 交互：可配置为按键说话（PTT）模式，正好匹配你的按钮
  • 服务端两种选择：
    • 官方云 xiaozhi.me：注册即用，个人免费用 Qwen 实时模型，控制台可选模型/音色/记忆/角色
    • 自建 xinnan-tech/xiaozhi-esp32-server：Python/Docker 一键部署，ASR/LLM/TTS 全可换，数据自己掌控
  • 旋钮音量：固件自带音量控制 MCP，EC11 映射为自定义输入即可

1~2 天出 demo免写协议层Web 控制台现成

方案 B：全自研（Arduino / ESP-IDF）

自己掌控每一层，适合二期把功能做深（自定义 UI、本地缓存、私有协议）。

  • 固件：ESP-IDF + I2S 驱动 + libopus 编码；PTT 按下开流、松开关流
  • 链路：Wi-Fi → WebSocket → 自建网关（FastAPI / Node）
  • ASR：FunASR/Paraformer（自建，中文强）或云端（讯飞/阿里/Whisper）
  • LLM：任何 OpenAI 兼容 API：DeepSeek、Qwen、GPT、Gemini、Ollama 本地
  • TTS：Edge-TTS（免费）/ CosyVoice / MiniMax / 讯飞
  • 设备 Web：ESP32 跑 HTTP Server（配网页 + REST + WebSocket 推送）+ mDNS（esp32.local）

工期 1~2 周完全可控需自己处理回声/断句/重连

✅ 建议路径：一期用方案 A 最快跑通全链路，验证「按钮说话 → 大模型 → 播放」体验；同时把自建服务端 xiaozhi-esp32-server 跑起来，实现你要的"页面配置模型 + 历史记录 + 喜好"。二期若需硬件差异化（多台对讲互联、离线唤醒词定制），再基于方案 A 的协议做定制固件，成本远低于从零自研。

🖥 旧 Mac 服务端部署要点（本项目选型）

  • 容器环境：装 OrbStack（轻快，个人免费）或 Docker Desktop / Colima
  • Intel Mac（x86）：官方 Docker 镜像直接可用，零障碍
  • Apple Silicon（M 系列）：官方镜像只有 x86，需按 docker-build.md 自行构建 arm64 镜像；或直接源码部署（Python 3.10 + JDK21 + MySQL + Redis，arm64 包齐全）
  • 内存建议：≥8GB → 全模块 + 本地 FunASR 识别；4GB → 全模块 + ASR 走云端 API
  • macOS 设置：系统设置关闭休眠（或 caffeinate -s）；路由器 DHCP 给 Mac 绑定静态 IP；开放 8000（WebSocket 音频）/ 8002（智控台+OTA）端口
  • 固件写入的地址：ws://旧Mac-IP:8000/xiaozhi/v1/ 和 http://旧Mac-IP:8002/xiaozhi/ota/
  • 成本：旧 Mac 功耗 ~10-30W，常年开机每月电费几块钱，无云服务器费用

09风险与注意事项

⚠️ 硬件坑

  • PSRAM 是硬门槛：必须买 N16R8（8MB Octal PSRAM），普通 N8R2 跑不动流式音频；R8 版 GPIO35~37 不可用（已在本方案避开）。
  • 供电：功放音量大时峰值电流 ~500mA，USB 口供电即可；用电池务必加 TP4056 保护 + 粗电源线，避免复位。
  • I2S 干扰：杜邦线过长会引入底噪/爆音，麦克风线 <15cm，必要时 SCK/WS 串 22Ω 电阻。
  • 回声（AEC）：PTT 半双工模式下喇叭放音时麦克风不采集，天然回避回声，这正是一期用按钮方案的优势。

☁️ 服务与成本

  • 官方云：个人免费（Qwen 实时模型），但历史/数据在第三方；正式使用建议自建服务端。
  • API 费用：DeepSeek 极便宜（百万 token 级 ¥1~2）；TTS 用 Edge-TTS 免费或 CosyVoice 自建。
  • 网络依赖：完全依赖 Wi-Fi，断网时设备播放本地提示音；二期可加 4G 模块（ML307，xiaozhi 已支持）。
  • 隐私：自建服务端 + 本地 Ollama 可实现全链路数据不出门（ASR/TTS 也用自建模型）。
  • 旧 Mac 常开：必须禁用休眠（合盖运行需接电源 + caffeinate/Amphetamine），路由器绑定静态 IP，否则设备找不到服务端亮红灯；建议关闭屏幕省电。
